A practical guide to entry points, service responsibilities, data flow and the PostgreSQL design on genweb2inhouse.

System at a glance

Entry points: the public API serves the browser on port 8100; the admin app is a separate entry point on port 8101. The inspected Compose setup has no separate shared API gateway or reverse proxy in front of them.

Deployment snapshot: server checked out to main after PR #1 was merged. This guide describes the app code at merge 37872fe; later documentation-only commits do not alter the application.

External dependencies

Newspaper websites provide sitemaps and article pages; OpenStreetMap Nominatim can resolve exact locations after initial publication. Publishers and geocoding services can fail or throttle requests. Area-level locations can remain approximate.

Service definitions: compose.yaml, compose.inhouse.yaml, deploy/inhouse-llm/. Public and admin FastAPI applications: app/public.py and app/api.py.
Pipeline & storage

From news to a map event

Newspapers → collector → articles + queued jobs (PostgreSQL) ↓ classifier claims job + lease ↓ Gemma extracts structured incident reports ↓ Python checks evidence, place and date → incidents ↓ candidate filter → EmbeddingGemma → two-way Gemma judge ↓ events + event_reports + matching decisions (PostgreSQL) ↓ public API → representative point and counts

Automatic collection: the current schedule is 08:00 and 20:00 Asia/Dhaka. Scheduled collection checks today and yesterday. A map date filter does not initiate a historical backfill.

Job safety: PostgreSQL rows are the queue; workers claim using FOR UPDATE SKIP LOCKED and a lease. Model calls and saved analyses are recorded; a failed later step can often reuse a saved answer. PostgreSQL coordinates tasks, while Python services do the work.

Why one incident can have many articles: location, category and date narrow candidates; embeddings rank them; a Gemma judge checks distinctive shared facts supported by quotes from both articles. If accepted, reports link to one event and the primary report is used for public counts. A different crime at the same location remains a separate event when the evidence does not match.

Operations & production handover

Access, verification and release

Public entry point

GET /api/config, /api/incidents, /api/stats, /api/version and /api/health. Responses are filtered to published event representatives. The browser checks the version for updates.

Admin entry point

Login, status, coverage, review, collection, matching inspection, merge/split and /docs. Browser mutations require session and CSRF checks; machine authentication uses an admin token.

What was verified on 28 October 2026

  • The full suite passed: 115 tests against an isolated temporary PostgreSQL container. The production database was not used for the destructive test fixtures.

Important operational detail: 20:00 is also an automatic collection slot. A restart at that time can interrupt that run; the collector is designed to recover interrupted work after restarting. Check the run history afterward to confirm it completed.

Before a public production launch

  • Database permissions: the inspected deployment uses the same PostgreSQL dcm account for services, with superuser privileges. Create separate limited roles for public API, admin, workers and migrations.
  • HTTPS and exposure: the inspected LAN deployment uses a self-signed certificate. Plan a trusted certificate, the intended public entry point, and controlled admin access before exposing it externally.
  • Release verification: PR #1 had no reported automated GitHub checks. Add an automated test pipeline and review evidence, including false merges and missed duplicate cases.
  • Data and reliability: observe service heartbeats, queue age, publisher errors, coverage and restore capability. The map represents newspaper reports, not all real-world crime; filters can reflect the primary report's fields.
This document is a point-in-time engineering guide, not a security audit or guarantee of production readiness. See repository code and deployment configuration for current behavior.
